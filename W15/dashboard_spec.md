## 儀表板規格 － 對應評分：visualization

### 這筆申請案的 SHAP 貢獻度圖（文字版，供本文件內直接檢視；正式儀表板會用下方 Plotly 程式碼渲染成互動長條圖）

```
PAY_0（還款狀態）      ██████████████████  推升違約機率（高，主要因子）
signup_at（帳齡）      ██████              推升違約機率（中，次要因子）
BILL_AMT1              （未使用，模型從未接收此特徵，無貢獻度可畫）
AGE                    （未使用，法遵禁用，無貢獻度可畫）
```

不誇大因果：這張圖只畫「模型真的有用到的兩個特徵」，`BILL_AMT1`／`AGE` 明確標「未使用」而
不是畫成 0（避免讓人誤以為「模型看過但影響是 0」，實際上是「模型從未接收這個輸入」，兩者
意義不同，圖上要分清楚）。

### 對應的 Plotly 程式碼（可請 AI Visual 協助精修成正式儀表板版本）

```python
import plotly.graph_objects as go

# 只放模型真的用到的特徵；BILL_AMT1／AGE 未使用，不進圖表，
# 避免讓人誤以為「有畫出來＝有參與判斷」。
features = ["PAY_0（還款狀態）", "signup_at（帳齡）"]
shap_contribution = [0.62, 0.24]  # 相對貢獻度，僅供本個案說明使用，非全體平均

fig = go.Figure(go.Bar(
    x=shap_contribution,
    y=features,
    orientation="h",
    marker_color=["#b6552e", "#a06a1e"]
))
fig.update_layout(
    title="申請案 APP-20260312-0417：SHAP 貢獻度（僅列模型實際使用的特徵）",
    xaxis_title="對違約機率的推升程度（相對值）",
    yaxis_title=None
)
```

| 要放的圖／欄位 | 給誰看（授信人員／客服／主管） | 為什麼需要這個，不是「順便放」 |
|---|---|---|
| 這筆申請案的 SHAP 貢獻度長條圖（只列 PAY_0、signup_at 帳齡兩項） | 授信人員 | 申請人或客服追問「為什麼被拒絕」時，授信人員要能當場指出具體是哪個因子、影響多少，不是回頭去翻模型碼 |
| PAY_0 還款狀態的個案值 + 全體申請人分布位置 | 授信人員 | 光看 SHAP 貢獻度看不出「這個人算不算異常」，要能對照全體分布才知道這筆案子落在哪個風險區間 |
| 客服話術卡（把 `case_explanation.md` 的商業語言版本直接嵌進畫面） | 客服 | 客服不需要懂 SHAP，只需要照著唸給申請人聽；把技術結果轉譯過的文字直接放上去，避免客服自己再翻譯一次出錯 |
| 模型使用特徵清單（明確列出「有用」跟「未用（含禁用原因）」兩欄） | 主管、客服 | 金管會或客訴一問「有沒有用年齡」，主管跟客服都要能立刻指給對方看——AGE／BILL_AMT1 明確標「未使用」，不是含糊帶過 |
| 本週 `qa_gate_passed`／`inference_ms`／`xai_coverage` 三項指標的通過狀態 | 主管 | 主管要知道這個模型是不是真的可以正式上線，不是只看 AUC 一個數字就放行 |

- **特別排除、決定不放的內容，以及理由**：
  - 不放整體 AUC／Precision／Recall 這類單一數字大字報——這正是這週要改掉的壞習慣，Client
    已經明講「如果你只能告訴我 AUC 0.89，那我沒辦法交代」，儀表板應該讓人一眼看懂具體理由，
    不是丟一個看起來很厲害但解釋不了個案的分數。
  - 不放 `AGE`、`MARITAL_STATUS`、`BILL_AMT1` 這些未使用或已禁用特徵的任何個人層級數值欄
    位——即使只是「顯示但不參與模型」，也可能讓看的人誤以為這些欄位有被納入判斷，或被誤用
    在儀表板之外的其他決策上，乾脆不顯示任何個人層級的這幾欄數值，只在「模型使用特徵清單」
    那張表用文字說明「未使用＋原因」。
  - 不放 `collection_flag`（催收紀錄）相關的任何欄位——W13 已確認這是目標洩漏特徵，不只模型
    不能用，儀表板也不該讓授信人員看到這個欄位進而誤判成「有用的風險訊號」。
