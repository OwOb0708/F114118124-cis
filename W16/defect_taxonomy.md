## 缺陷分類 － 對應評分：defect_taxonomy

範本檔案：`credit_pipeline_v2.py`（系統提供，處理的是我們從 W10 開始的同一份 `credit_dirty` 專案資料）

| 你發現的問題 | 出現在哪裡（檔案／行為） | 為什麼這個問題該讓專案被退件 |
|---|---|---|
| 特徵洩漏 | `feature_cols` 裡包含 `LEAK_FUTURE_DEFAULT`，直接餵進模型 | 這個欄位本質上就等於答案（跟目標欄位 `default` 高度重疊，事後才會知道），用它訓練出來的準確率沒有任何意義，是最嚴重的一種造假結果 |
| 沒有固定隨機種子 | `train_test_split(...)`、`RandomForestClassifier(...)` 都沒設 `random_state` | 同一份程式碼重跑兩次會拿到不同的訓練/測試切分與不同模型，別人沒辦法重現你的結果，也沒辦法驗證你回報的分數 |
| 訓練/測試集互相污染 | `scaler.fit_transform(X)` 在 `train_test_split` **之前**對全體資料做 `fit` | 測試集的統計資訊（平均數、標準差）透過標準化參數偷偷洩漏進訓練流程，測出來的分數會比真正上線後樂觀 |
| 路徑寫死 | `DATA_PATH = "C:/Users/pm/Desktop/credit-dirty_v2.csv"` | 這是原作者個人電腦上的絕對路徑，換一台機器、換一個人執行就會直接找不到檔案，程式碼沒有可攜性 |
| 缺值處理不當 | `df["BILL_AMT1"] = pd.to_numeric(df["BILL_AMT1"], errors="coerce").fillna(0)` | 把「金額看不懂／缺漏」跟「金額真的是 0 元」混為一談，會讓模型學到錯誤的訊號，而且註解寫「先當作沒欠款處理」沒有進一步處理，等於默認接受這個誤導 |
| 沒處理類別不平衡 | `train_test_split` 沒有 `stratify=y`；最後只印 `accuracy_score`，模型也沒設 `class_weight` | 完全沒有檢查或因應正負樣本比例，只看整體準確率在不平衡資料上容易失真（多數類別猜對就能拿高分），沒有任何證據顯示模型真的學到少數類別的模式 |
| 依賴沒鎖版本 | 檔案開頭註解只寫 `pip install pandas scikit-learn`，沒有版本號 | 不同時間、不同機器安裝到的套件版本可能不同，同一份程式碼在別人環境跑出來的結果不保證一致，「在原作者機器上跑得動」這句註解本身就是警訊 |
| 靜默丟資料列 | `df.drop_duplicates()`、`df = df[df["ID"] != ""]` 兩行都沒有印出或記錄刪掉了幾筆 | 資料清理完成後只印了一句「資料清理完成」，沒人知道實際上被過濾掉多少筆、比例是否合理，清理過程完全不可追溯 |
