## 2. 欄位語意與後續用途（context_clarification）

> 以下為向「客戶（業務單位）」與「專案經理 PM」詢問後取得的回覆（本次於 2026-10-02 war room 內確認）。

| 欄位 | 業務語意（客戶回覆） | 後續用途影響 |
|---|---|---|
| ID | 申請案編號，之後要與「還款紀錄」依 ID 對帳 | 不可自行產生編號；ID 是跨週資料串接的關聯鍵 |
| AGE | 申請時年齡；`-1` 是舊系統「未填」預設值 | 業務規則只核卡給 18 歲以上，但本欄不是 missing_rate 檢查欄位 |
| PAY_0 | 還款狀態代碼（-2 無應繳、-1 全額繳清、0 只繳最低、1+ 為逾期月數）；`late` 僅知有逾期、未知確切月數 | `late` 無法對應到任何合法代碼，只能視為資訊不足 |
| BILL_AMT1 | 最近一期帳單金額；空白＝該期還沒出帳，`n/a`＝帳務同步失敗 | 兩者成因不同，不應用同一方式處理 |
| signup_at | 帳戶開立時間，可能為 UTC、台北時間（+08:00）或僅日期格式 | 三種合法格式換算後指向同一時間點，正規化後資訊量為零 |
| MARITAL_STATUS | 申請人自填婚姻狀態；`??`／`NULL` 表示拒答 | 依法遵規定不得用於授信模型，不值得花力氣清洗 |

> PM 另外確認：「清洗後的資料將用於 W13 探索式分析與 W14 建模；本週的清洗決策會直接影響後續分析與模型品質。」——因此 ID 的唯一性與可追蹤性，是本週清洗中優先順位最高的規則。

## 3. 清洗規則（de_rules）

| # | 規則 | 理由 |
|---|---|---|
| 1 | ID 空白的列直接排除（隔離），不清洗、不補值 | ID 是跨週對帳與分析的關聯鍵，自行產生編號會污染 W13/W14 的資料串接 |
| 2 | ID 重複的列，保留第一筆、其餘排除 | 避免同一筆申請案被重複計入 missing_rate 與後續統計 |
| 3 | PAY_0 的 `late` 標準化為缺值（NULL），不猜測成任何數值代碼 | Client 僅能確認「有逾期、未知月數」，無根據對應到 -2～9 的任何合法值 |
| 4 | AGE 的 `-1` / `unknown` 標準化為缺值，但不補值 | 本欄不是 missing_rate 檢查欄位，且補值可能誤導 W14 建模 |
| 5 | BILL_AMT1 的 `n/a` 標準化為缺值；空白維持缺值 | 兩者雖成因不同，但都不是能由清洗端猜出正確金額的情況 |
| 6 | signup_at 的 `not-a-date` 標準化為缺值，不做時區換算 | 換算與否不影響 missing_rate；是否需要時區資訊留給下游決定 |
| 7 | MARITAL_STATUS 的 `??` 標準化為缺值，不補值 | 依法遵規定本欄不得用於模型，沒有填補的價值 |

執行順序：規則 1 → 規則 2 → 規則 3～7（欄位標準化，互不影響順序）。
