## 缺陷逐項確認 － 對應評分：defect_triage
| 缺陷編號 | 欄位 | 缺陷類型 | 影響列數 | 商業影響 |
|---|---|---|---|---|
| DQ-01 | ID | 主鍵空值/重複 | 29（空值 12、重複鍵 17） | 主鍵是後續所有分析與建模串接客戶紀錄的依據，空值或重複會讓同一客戶被算成兩筆、或無法追溯回原始申貸紀錄，直接影響違約率統計的正確性。 |
| DQ-02 | AGE | 負值/空白/unknown | 163（清洗後保留列中仍有 141 筆為 NULL） | 年齡是本次專案鎖定「25–35 歲聯徵薄」族群的關鍵篩選欄位，若用平均值或眾數填補會人為壓縮風險分布、掩蓋掉真正該被關注的年輕族群樣本。 |
| DQ-03 | signup_at | 3 種時間格式混用 | 166（清洗後仍有 50 筆無法解析） | 註冊時間影響「資歷長短」這類衍生特徵，格式不一致會讓同一時間點在不同列被誤判為不同時期，時間序列分析會直接失真。 |
| DQ-04 | BILL_AMT1 | 金額缺漏或非數值 | 147（清洗後保留列中仍有 127 筆為 NULL） | 帳單金額是判斷還款能力與違約風險的核心特徵之一，缺漏若被當成 0 處理，會讓實際上「資料不完整」的客戶被誤判為「零消費、低風險」。 |

## 清洗規則 － 對應評分：de_rules
| 欄位 | 規則（replace／設 NULL／整列拒絕） | 理由 |
|---|---|---|
| ID | 空值：整列拒絕（不補值） | 主鍵不可用任何方式代填——補一個假 ID 等於捏造一筆不存在的客戶紀錄，比留著空值更危險。 |
| AGE | 負值／空白／unknown：設為 NULL | 不用平均值掩蓋資料缺漏；NULL 讓下游分析（如 W12 EDA）明確知道這是「不知道」而不是「剛好等於平均值」。 |
| signup_at | 統一轉換為 ISO-8601 UTC；三種已知格式可解析的一律換算，換算不了的（如「not-a-date」字面值）設為 NULL | 統一時區與格式，才能做跨列的時間比較；無法解析的資料如果硬猜一個時間點，比留白更誤導人。 |
| BILL_AMT1 | 缺漏（空白／"n/a"）：保留列、值設為 NULL，聚合計算時排除並在報告揭露 | 這欄缺漏率高達 6 成以上，直接刪列會讓保留下來的資料集失去代表性；用 0 或均值填補則會製造不存在的低風險假象。 |
| (ID, signup_at, BILL_AMT1) 三欄完全相同 | 判定為重複列，隔離（quarantine）不計入輸出，但**不是靜默刪除**——原始筆數與被隔離筆數都留在 transformation_report.md | 重複列多半是同一筆申請被系統重複寫入，保留兩份會讓這位客戶在統計上被算兩次，但直接刪除又怕誤刪合法的巧合重複，所以選擇「隔離並記錄」而非直接丟棄。 |
| LEAK_FUTURE_DEFAULT | 從輸出中整欄移除 | 這欄位的值等於 default 的完整複本（目標洩漏），雖然本週不做特徵選擇，但留著它會讓 W13/W14 的人（包含未來的我自己）誤用成一個「準確率100%」的假特徵。及早拿掉，比留給下週的自己一個陷阱更負責任。 |
